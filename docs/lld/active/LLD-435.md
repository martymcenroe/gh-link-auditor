# LLD-435: C3 credit when the dead URL's 200 is a redirect to our candidate

**Issue:** #435
**Status:** Active

## 1. Problem

`score_c3_dead_http_status` awards 0/10 whenever the dead URL returns 2xx — the "it looks alive, so a fix is suspicious" heuristic. For the GitHub org-rename class the dead URL 200s *via redirect to the candidate URL itself*. Gate 5 already blesses exactly this shape (`redirect_to_renamed=True`), so the pipeline simultaneously says "this is a real fix" (gate) and "no credit" (score).

Consequence: the class is capped at 80/100 and can never reach the 90 threshold. Evidence: `act-now-coalition/covid-data-model` post-#407 scores 80 with C5 clean 15/15 and C3 0/10.

## 2. Solution

In `score_c3_dead_http_status`, when the status is 2xx, award full credit iff **both**:

1. `gates._is_redirect_to_renamed_location(dead_url, final_url)` — the same judgment gate 5 makes. Reusing it (rather than writing a second redirect heuristic) is what keeps gate and score from ever disagreeing; it is also deliberately conservative, excluding same-host `http→https` / `www` normalization redirects.
2. The redirect's `final_url` matches `candidate_url` under the existing `_are_urls_near_equivalent(..., http_check=None)` normalization — string-only patterns (identical, escape, `index.html`, percent-encoding, stray trailing, truncation), no live fetch.

Condition 2 is the load-bearing one: it proves the redirect confirms *our specific proposed replacement* as the canonical target, not merely that the dead URL moved somewhere.

Evidence on credit: `{"reason": "redirect_to_candidate", "status_code": ..., "final_url": ...}` so operators can audit why the credit was granted.

Plain 2xx with no rename-redirect, or a rename-redirect landing somewhere other than our candidate, stays 0 — the resurrection heuristic remains correct there.

`scores` importing from `gates` is a new edge but not a cycle: `gates` imports `network`, `preflight.report`, `repo_quality` — never `scores`. Module-level import (not function-local) keeps the name monkeypatchable.

## 3. Tests

`tests/unit/preflight/test_scores.py::TestScoreC3`, all via injected `http_check` (no network):

- `test_full_points_when_200_redirects_to_candidate` — cross-host redirect to the candidate → 10, `reason=redirect_to_candidate`
- `test_full_points_on_github_org_rename` — the act-now-coalition shape (same host, owner differs) → 10
- `test_zero_when_200_without_redirect` — `final_url == dead_url` → 0 (unchanged behavior)
- `test_zero_when_redirect_lands_elsewhere` — rename redirect, but not to our candidate → 0
- `test_zero_when_same_host_scheme_normalization` — `http→https` same host → 0; pins gate 5's conservatism so a future "helpful" widening can't silently credit trivial redirects
- `test_full_points_when_redirect_matches_candidate_modulo_index_html` — normalization reuse
- Existing 4xx / 5xx / None / no-op cases unchanged.

## 4. Acceptance

- New tests green, existing C3 tests unchanged, full suite green, lint clean.
- Post-merge re-run of `act-now-coalition/covid-data-model` scores **90** → verdict `pass`.

## 5. Risk

The credit is gated behind gate 5's own conservative rename test AND an exact-candidate match, so it cannot fire for a genuinely-resurrected URL (no redirect → no credit) or for a redirect to an unrelated target. The remaining hard gates are untouched; C3 credit alone cannot push a bad candidate through.
